## Delight

1. **The original product thesis is still the right one.** ysbang’s `search-by-price` still FAILs `forbidden-name` today. The contract is doing the job it was created for: cap surface area. Without it, freeze (ma-browser v0.13 F*) would industrialize the 38-file mess.
2. **`bb-eval` is fast and honest about being static.** Sub-second, no Chrome, exit 0 iff no FAIL. The 2026-09-07 Check 0 (compile `(body)` like site.ts) and `no-ghost-api` are the two checks that actually match production. 1688/search and xhs/search both go green for the right reasons: single expression, no `bb.*`, URL after `@meta`.
3. **Three domains is the correct split.** Ecommerce = cart/order; pharma-data = records; social-media = browse/read/engage/create. The ADRs are specific (cart checks would be N/A; XHS `xsecToken` must not be generalized). Intent-vs-filter (`search` vs `feed` vs `user-notes`) is the one idea worth keeping forever.
4. **Soul.md is unusually useful.** Screenshot-driven 1688 fixes, the inverted “anonymous function” verdict, SM-2.10 ghost-API migration — an agent can actually reconstruct what is true. That is rarer than a wiki.
5. **Wiki + SKILL + contract layering is navigable** once you know: contract is normative, SKILL is the agent prompt, wiki is the map, soul.md is the crime scene.

## Pain

1. **The official starting point fails the official checker.** All three TEMPLATE.js still call `bb.goto` / `bb.$$eval` / `bb.fetch`. `no-ghost-api` FAIL. SKILL and playbooks still talk like a Playwright handle exists. SM-2.10 migrated *adapters*; the repo that teaches adapters did not catch up. A freeze generator that copies TEMPLATE will emit drafts that cannot `site_run`.
2. **`./tools/bb-eval` is a lie.** File is `-rw-r--r--`. README / wiki / getting-started all say `./tools/bb-eval`. First-time agent hits Permission denied.
3. **Envelope split.** Ecommerce contract + 1688 source use `success`. Social-media contract + wiki envelope page use `ok`. Pharma TEMPLATE uses `success`. An agent (or a freeze generator) that “learns the envelope once” will emit the wrong boolean key half the time. `bb-eval` does not check which key you used.
4. **PHR-8 fights the pharma contract.** Contract: one file per dbKey, name = `yaopinjiage`. Check: canonical set is `auth|list|item|search|export|related`. Real adapter therefore always WARNs. Fitness signal is noisy.
5. **Static green is easy to over-claim.** soul.md already walked this back: XHS 11/15 never had a real-browser run; 1688 writes were blocked by React `isTrusted` / CHIPS, then `render` was unblocked with a warm-up recipe (`44b0899`) — still daemon/page work, not eval. The repo’s older “0 fail = production ready” sentence was corrected in soul.md and should stay corrected.
6. **Command rename drift.** Runtime CLI is `ma-browser`. Every `@meta.example`, SKILL step, and wiki still says `bb-browser site ...`. v0.13 F7 will print `ma-browser` hints; evolver will keep teaching the old binary unless M0 lands.
7. **Verifier docs are one version behind the tool.** `verify-adapter-runtime-shape.js` header says v3, no `bb` global. wiki `runtime-verification.md` still tables mock `bb.goto`. Two sources of truth.
